# WP-03 附录 · 墨墨词库主题精读

> 把间隔重复里的词表重组成连贯文章：一个词只讲解一次，脚注给出贴合此处的英英释义。

📕 **电子书：[`momo-reading.epub`](momo-reading.epub)**（317 KB，EPUB 3，epubcheck 零错误零警告）——这是唯一的发布物。

## 这是什么

背单词软件按遗忘曲线安排复习，效率高，但词是孤立的——记住的是卡片正反面的配对，
不是这个词在句子里怎么活动。这份附录把当前学习计划里的全部词汇取出来，
重组成托福难度的文章，让每个词在语境里再出现一次。

**全书 25 章按题材编排，不按日期。** 一个词只讲解一次；后面任何一章再出现，
不论什么词形，都自动标成「复现」，不再给释义。

> **2026-08-31：废除了「一天一篇」。**
> 中间有 11 章是按天写的——当天背的新词在当天讲解。问题不在文章写得不好，
> 在于**「这些是你今天背的词」这个前提一天就过期**：断更三天，那批词早已被
> 复习过两三轮，为它们写的那一篇是在回答一个别处已经答过的问题。
> 于是断更的惩罚是复利的：停得越久，积压越死，越没有理由回来。
> 而主题文章不会这样——一个月后再读采石场那篇，一样好。
>
> 那 11 章的 524 个词已**全部打乱重编成 12 章主题精读**（下表 14–25）。
> 13 章原有的主题精读没有动：那是全书 1124 个词、17,155 词正文，是能用的部分。

这本书**只以 EPUB 发布**，读它的地方是文石 Boox 的 NeoReader。
早期同时出过一个网页版（`gh-pages` 上的 `vocab/momo.html`），已经不再更新——
实际的阅读全部发生在电纸书上，维护两套输出只是让它们悄悄不一致。
旧链接保留不删，以免外部引用 404，但内容停在最后一次网页构建。

## 怎么用

`momo-reading.epub` 是给电纸书用的，主要在文石 Boox 的 NeoReader 上读。
NeoReader 对 JavaScript 支持极弱，所以正文是纯 HTML + CSS，没有任何交互。
Boox 是灰度屏，含义一律用字重和下划线表达，不用颜色。

正文里有两种标记：

- **粗体 + 实线下划线**：该词在本章**首次讲解**，后面的角标点开是贴合上下文的释义
- 虚线下划线：该词在你计划里**已经有了**，此处是**复现**，不带释义——用来自测

**凡是学习计划里的词，出现一次就标一次**，包括词形变化（`system`/`systems`、
`tiny`/`tinier`），也包括后面章节才讲解的词。所以「**没有标记 = 没有你要复习的词**」，
可以放心跳读；反过来虚线词不该略过，那正是检验记忆的地方。

这条保证由构建时的断言强制：只要有计划内的词漏标，构建直接失败。

其余：每章末尾是「**本章作文词**」——这篇文章里出现过的学术词表（AWL）词，
按 AWL 子表先后排，回答的是「哪些词值得写进作文」，而不是「这章教了什么」；
所以别的章教过、本篇用到的词也算，因为**这篇正是它的用法示范**。
每条不给释义，而是直接引这个词在本篇里的那半句原文——
`The rigor of the **process** is its only real defence`。
释义脚注里已经有了，长按还有词典；写作要用的是搭配，而它本来就躺在正文里。
书末另有四章，**全部不给释义**——正文脚注里有，长按还有词典，再印一遍是白费纸。

**一、词根词簇（拆得开的）**：5 族 35 个词，`cred-` `voc-/vok-` `tract-` `vert-/vers-` `spec-/spic-`。
给的不是意思，是**前缀到底做了什么**。这一章有个反直觉的要点：能拆开的词更容易记**错**，
不是更容易记住——`disinterested` 拆出来像「不感兴趣」（其实是「不偏袒」），
`inept` 拆出来像 in- 加 ept（英语里没有 ept 这个词）。**能拆开的感觉和认识这个词的感觉是同一种感觉**，
于是复习时被判成「会了」。但 `tract-` 一族拆得同样干净却一点不难，
所以罪不在「可分解」，在**拆出来的意思看着对而实际不对**。
`cred-` 那一族还特意留了空格：计划里只有 credulous（信的人）和 incredible（被信的事），
缺的恰好是能把「人 / 事」这个轴分开的另外两格。

**二、近义词簇（拆不开的）**：6 组 44 个词，鄙视轻蔑 / 嘲讽讥笑 / 阻碍抑制 / 欺骗伪装 / 逃离躲避 / 减少缩小。
这些词的失败方式不是想不起来，是**选错**：「看不起」这个方向立刻就到了，
到不了的是这个方向上的哪一个成员。所以给每个词的是**分界线**——
sneer 一个人可以不出声，jeer 一群人出声起哄；dissimulate 藏起真的，feign 装出没有的；
abate 是风和疼痛**自己**减弱，reduce 是人去减。

**三、作文词表（AWL）**：全书出现过的 226 个学术词表词按子表 1–10 汇总，
每条只给这个词在正文里的那半句原文和它的 AWL 词族。
每章末尾那份清单只能回答「这一篇里哪些词能用进作文」，看不见的是全局：
哪几档还很空、哪个词族你只认得其中一个成员。词族尤其要紧，AWL 以词族计数，
会用 `analysis` 不等于写得出 `analytical`，考场上卡住的正是这个转换。
词族分「已在计划」与「未收」两栏——**226 个词里 196 个是全族独苗**，
`evident` 没有 `evidence`，`stable` 没有 `stability`。
阅读时这不要紧（同族词形近，认得主词就够），写作时要填对那个槽，缺的就调不出来。

**四、学术写作框架**：篇章与段落骨架、句间动作（让步反驳、因果分级、限定弱化、强化、举例、定义），
例句全部取自你读过的正文，并标出在第几章。

卷首一页学习进度；查词交给设备——Boox 长按即可调用系统词典，EPUB 不内嵌词库，省体积。
也正因为查词只是长按一下，书里不再附 A–Z 全书词表：那只是把 1648 条释义原样再印一遍。
正文脚注保留——词典给的是通用义，脚注给的是**此处上下文**的意思。

### 为什么「作文词」用 AWL，不用出现次数

最直觉的做法是按词在书里复现多少次来标。实测下来是反的：

| 书内复现次数 | 词数 | 其中顽固词 | 其中 AWL |
| --- | --- | --- | --- |
| 1 次 | 41 | 14.6% | 2.4% |
| 2 次 | 774 | 16.0% | 10.2% |
| 3 次 | 264 | 18.2% | 16.3% |
| 4–5 次 | 165 | 9.7% | 26.1% |
| 6–9 次 | 69 | 2.9% | 18.8% |
| 10 次以上 | 50 | **2.0%** | 18.0% |

复现最多的前 30 名是 `rather than` `system` `begin` `become` `even` `long` `still`，
前 50 名里只有一个是顽固词——**书内高频 ≈ 英语常用词 ≈ 早就会了**。
而 AWL 占比随复现次数上升，方向正好相反，正好捞出被频率掩盖的那层学术词。

用法：插 USB 后跟我说一声「拷到我的 Boox」就行。设备走 MTP，没有盘符，
普通的复制粘贴看不到它，所以由 `lib/deploy_boox.py` 通过 COM 接口传，
传完会把文件读回来做哈希校验——MTP 有时会在写坏的情况下仍报成功。

书的 UUID 固定不变，所以更新版会**原地覆盖**，不会在书架上堆出一排同名书。
拷完在设备上刷新一下书库即可看到。

## 数据来源

词表通过[墨墨开放 API](https://open.maimemo.com/) 的 `query_study_records`
接口导出，仅包含已进入学习计划的词。开放平台不提供词书目录接口，
因此尚未开始学习的词不在其中——随着学习推进重新导出即可增量扩充。

文章与释义均为原创，不含任何受版权保护的原文摘录。

## 怎么更新

跟我说一声「更新单词书」就行，不用自己敲命令。流程是固定的：

```
node pull.mjs        拉学习计划全量记录 → 待收录的新词攒进 pending.txt
   ↓
攒够一个题材能撑起约 40 个词 → 写成一章 → node verify.mjs <章名>
                              必须 PASS，不过就重写
   ↓
node build-epub.mjs  重编 EPUB（唯一发布物）
   ↓
epubcheck 零错误 → py lib\deploy_boox.py 传到设备
```

**决定何时开一章的是题材，不是日期。** 新词就在 `pending.txt` 里攒着，
直到某个题材能诚实地装下四十个左右。这确实放弃了一件事：
词不再在计划安排的那一天于文章里见面。但证据表明这个时机没买到多少东西——
当前 200 多个顽固词**全都已经在书里讲过**，而且是准时讲的，照样没记住。

反过来，一个题材只撑得住二十个词就动笔，得到的是「为剩下的词单开一节」——
那种小节永远写得很漂亮，所以才危险，它正是旧的每日篇读起来散架的原因。**宁可再等。**

管线在 `D:\projects\momo-reading\`，`data/chapters/*.json` 是唯一内容源。
`verify.mjs` 是硬门禁：逐章核对每个目标词在正文里恰好标记一次、生词表与正文严格一一对应——
不 PASS 就不出版本，绝不产出缺词的章节。
